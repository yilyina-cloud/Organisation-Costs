Описание архитектуры AS-IS и TO-BE

AS-IS

Текущая кассовая система VitaStore зависит от локальной инфраструктуры магазина.

В каждом магазине используются локальный POS, локальная БД и отдельные интеграции с оборудованием. Обмен с центральными системами выполняется не в реальном времени, а через ночную выгрузку XML/FTP.

Основные проблемы:

- высокая стоимость поддержки локальных серверов и БД;
- зависимость POS от конкретных драйверов оборудования;
- сложное подключение новых магазинов;
- отсутствие единой облачной точки интеграции;
- при отказе локальной инфраструктуры работа магазина может остановиться.

TO-BE

В целевой архитектуре используется Cloud POS с тонким клиентом в магазине.

Основная бизнес-логика и данные продаж переносятся в Cloud POS Backend и Managed POS DB.

В магазине остаются только компоненты, необходимые для работы кассы и offline-режима:

- Thin POS;
- Sync Component;
- HAL;
- локальный кеш;
- банковский терминал;
- фискальный регистратор.

Offline-режим

Для продолжения продаж без интернета локальный кеш содержит минимальный набор актуальных данных: товары, цены и необходимые настройки.

Продажи, созданные offline, сохраняются Sync Component в локальной очереди.

После восстановления соединения накопленные операции автоматически передаются в Cloud POS Backend.

Защита от дублей

Каждой продаже при создании присваивается уникальный `operationId`.

При повторной отправке операции после восстановления связи используется тот же `operationId`.

Cloud POS Backend обрабатывает запросы идемпотентно: перед записью продажи проверяется `operationId`.

Если операция уже была сохранена, повторная отправка не создаёт вторую продажу. Backend возвращает подтверждение, что операция уже обработана.

В Managed POS DB для `operationId` используется уникальное ограничение.

Это защищает от дублей в ситуации, когда продажа была успешно записана на сервере, но соединение оборвалось до получения подтверждения магазином.

Работа с оборудованием

HAL предоставляет единый интерфейс для банковских терминалов и фискальных регистраторов.

При подключении нового оборудования меняется адаптер HAL, а не Cloud POS.

Это снижает зависимость кассового приложения от конкретных моделей устройств и драйверов.

Интеграции

Payment Gateway используется как единая точка взаимодействия с банками и эквайерами.

Integration Service обеспечивает обмен Cloud POS с корпоративными системами:

- SAP ERP — товары, цены, учётные данные;
- Promo Engine — промоакции;
- Smart Fulfillment — Click & Collect и логистика.

AI SKU Matching Service и Validation Service используются при онбординге новых магазинов для автоматизации сопоставления номенклатуры.

Итог

Целевая архитектура убирает полноценные локальные серверы и БД из магазинов, но сохраняет возможность продолжать продажи при временной потере связи.

Cloud POS централизует бизнес-логику и данные, HAL изолирует работу с оборудованием, а Sync Component обеспечивает надёжную синхронизацию offline-продаж без создания дублей.
